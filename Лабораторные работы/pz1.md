# Лабораторная работа № 1

**Модуль 1. Основы Docker**

**Тема:** Установка Docker, управление образами и контейнерами, перенос веб-приложения в Docker.

**Операционная система:** Linux (Ubuntu / Debian или другой совместимый дистрибутив).

## Цель лабораторной работы

Освоить установку и первичную настройку Docker в Linux, изучить взаимодействие Docker Client и Docker Engine, научиться загружать образы, создавать и управлять контейнерами, просматривать их состояние и журналы работы. Получить практический опыт упаковки собственного веб-приложения в Docker-образ и запуска приложения в изолированном контейнере.

**Ожидаемый результат:** работающее веб-приложение, доступное через браузер по адресу `http://localhost:8080`, собственный Docker-образ и отчёт о выполненных действиях.

## Задание

### Шаг 1. Подготовка Linux и установка Docker

1. Откройте терминал Linux и определите название и версию установленного дистрибутива.
2. Проверьте наличие Docker в системе. Если Docker уже установлен, определите его версию.
3. Если Docker отсутствует, установите Docker Engine и Docker CLI, используя официальную инструкцию для своего дистрибутива.
4. Проверьте состояние службы Docker через `systemctl`.
5. Убедитесь, что служба Docker запущена и может принимать команды.
6. Выполните запуск тестового контейнера `hello-world`.
7. Зафиксируйте версию Docker и результат тестового запуска для отчёта.

### Шаг 2. Изучение компонентов и архитектуры Docker

1. Получите информацию о клиентской и серверной частях Docker.
2. Определите версии Docker Client и Docker Engine.
3. Получите сведения о сервере Docker: количестве контейнеров, количестве образов и используемом драйвере хранения.
4. Определите, какой процесс Linux отвечает за работу Docker Engine.
5. Выясните, каким образом Docker CLI взаимодействует с Docker Engine.
6. Запишите в отчёте назначение Docker Client, Docker Daemon, Docker Image и Docker Container.

### Шаг 3. Загрузка и изучение Docker-образов

1. Найдите официальный образ `nginx` в Docker Hub.
2. Загрузите образ `nginx:alpine` на локальный компьютер.
3. Выведите список доступных Docker-образов.
4. Определите идентификатор, тег и размер загруженного образа.
5. Получите подробную информацию об образе.
6. Установите, чем образ Docker отличается от контейнера, созданного на его основе.

### Шаг 4. Создание первого рабочего контейнера

1. Создайте контейнер с именем `lab1-web` на основе образа `nginx:alpine`.
2. Запустите контейнер в фоновом режиме.
3. Настройте доступ к веб-серверу через порт `8080` локального компьютера.
4. Откройте в браузере `http://localhost:8080` и убедитесь, что отображается стандартная страница Nginx.
5. Выведите список запущенных контейнеров и найдите созданный контейнер.
6. Просмотрите журналы работы контейнера.
7. Остановите контейнер и проверьте, что веб-сервер перестал отвечать.
8. Повторно запустите тот же контейнер и убедитесь, что сайт вновь доступен.
9. Зафиксируйте результаты проверки.

### Шаг 5. Подготовка собственного веб-приложения

Создайте каталог `docker-lab1` в домашней директории Linux. Внутри каталога создайте HTML-файл `index.html`, который будет представлять собой простую информационную страницу.

На странице должны присутствовать название лабораторной работы, сведения об авторе, описание назначения Docker и сообщение об успешном запуске приложения в контейнере.

Добавьте собственное оформление с использованием CSS. Страница должна иметь заголовок, основной текст и хотя бы один оформленный информационный блок.

Проверьте корректность HTML-разметки и убедитесь, что исходный файл находится в каталоге проекта.

### Шаг 6. Создание собственного Docker-образа

1. В каталоге `docker-lab1` создайте файл с названием `Dockerfile` без расширения.
2. Выберите официальный образ Nginx в качестве базового.
3. Настройте копирование собственного файла `index.html` в каталог веб-сервера внутри образа.
4. Укажите порт, используемый веб-сервером внутри контейнера.
5. Соберите собственный Docker-образ с именем `lab1-site` и тегом `1.0`.
6. Проверьте успешность сборки и наличие созданного образа.
7. Сравните размер собственного образа с размером исходного образа `nginx:alpine`.
8. Объясните в отчёте назначение инструкций `FROM`, `COPY` и `EXPOSE`.

### Шаг 7. Запуск собственного приложения в Docker

1. Остановите и удалите ранее созданный контейнер `lab1-web`, освободив порт `8080`.
2. Создайте новый контейнер с именем `lab1-site`, используя собственный образ `lab1-site:1.0`.
3. Настройте проброс порта `8080` компьютера на порт `80` контейнера.
4. Запустите контейнер в фоновом режиме.
5. Откройте `http://localhost:8080` в браузере.
6. Убедитесь, что отображается ваша HTML-страница, а не стандартная страница Nginx.
7. Проверьте состояние контейнера и журналы его работы.
8. Получите подробную информацию о работающем контейнере.

### Шаг 8. Проверка жизненного цикла контейнера

1. Остановите контейнер `lab1-site` и проверьте доступность веб-приложения.
2. Запустите контейнер повторно и убедитесь, что приложение восстановило работу.
3. Удалите контейнер, не удаляя собственный Docker-образ.
4. Создайте новый контейнер из того же образа.
5. Проверьте, что веб-приложение работает без изменения исходных файлов.
6. Определите, сохраняется ли Docker-образ после удаления контейнера.

## Подсказки по ключевым частям

**Проверка системы и Docker**

```bash
cat /etc/os-release
docker --version
sudo systemctl status docker
sudo docker version
sudo docker info
```

Для первоначальной проверки используйте `sudo docker run --rm hello-world`. Параметр `--rm` удаляет тестовый контейнер после завершения его работы.

Если Docker установлен, но служба не запущена, используйте `sudo systemctl start docker`.

**Загрузка образов и создание контейнеров**

```bash
sudo docker pull nginx:alpine
sudo docker image ls

sudo docker run -d --name lab1-web \
  -p 127.0.0.1:8080:80 nginx:alpine
```

Параметр `-d` запускает контейнер в фоновом режиме, `--name` задаёт его имя, а `-p` связывает порт компьютера с портом контейнера. Адрес `127.0.0.1` ограничивает доступ локальным компьютером.

**Управление контейнерами**

```bash
sudo docker ps
sudo docker ps -a
sudo docker logs lab1-web
sudo docker stop lab1-web
sudo docker start lab1-web
sudo docker inspect lab1-web
```

Команда `docker ps` показывает запущенные контейнеры, а `docker ps -a` — также остановленные.

**Создание Dockerfile**

Для переноса статического веб-приложения достаточно базового образа Nginx, копирования HTML-файла и указания внутреннего порта.

Пример основной структуры:

```dockerfile
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
EXPOSE 80
```

Инструкция `EXPOSE` документирует порт контейнера, но сама по себе не публикует его на компьютере. Для доступа через браузер используется параметр `-p` при запуске.

**Сборка и запуск собственного образа**

```bash
sudo docker build -t lab1-site:1.0 .

sudo docker run -d --name lab1-site \
  -p 127.0.0.1:8080:80 lab1-site:1.0
```

Точка в конце команды `docker build` обозначает текущий каталог как контекст сборки. Выполняйте эту команду из каталога, содержащего `Dockerfile`.

**Проверка работоспособности**

```bash
curl http://127.0.0.1:8080
sudo docker logs lab1-site
```

Если страница не открывается, проверьте состояние контейнера, корректность проброса портов и наличие другого процесса, занимающего порт `8080`.

Если команды Docker не выполняются без прав администратора, используйте `sudo`. Добавление пользователя в группу `docker` предоставляет ему привилегии, сопоставимые с root, поэтому не меняйте права доступа без необходимости.

## Советы по улучшению работы

**Используйте понятные имена.** Называйте образы и контейнеры так, чтобы по имени можно было определить их назначение. Применяйте версии образов в виде тегов.

**Контролируйте состояние контейнеров.** После запуска проверяйте не только доступность веб-страницы, но и состояние контейнера с помощью `docker ps`, а также отсутствие ошибок в журналах.

**Улучшите внешний вид веб-страницы.** Создайте аккуратное оформление, используйте согласованные цвета, читаемые шрифты и адаптацию страницы под разные размеры экрана.

**Обеспечьте воспроизводимость.** Проверьте, что предоставленных файлов достаточно для повторной сборки образа на другом компьютере с установленным Docker.

**Не включайте лишние файлы в проект.** Сохраняйте только те материалы, которые необходимы для сборки приложения, проверки результата и подготовки отчёта.

**Документируйте обнаруженные ошибки.** Если при установке, сборке или запуске возникают проблемы, зафиксируйте их причины и способы устранения. Это позволит продемонстрировать понимание процесса работы.

## Вопросы для рефлексии

1. **Почему Docker использует образы для создания контейнеров?** Что изменилось бы, если бы каждое приложение приходилось устанавливать и настраивать непосредственно в операционной системе?

2. **Что произойдёт, если удалить работающий контейнер, но сохранить его Docker-образ?** Какие действия потребуются для восстановления приложения и почему?

3. **Почему веб-сервер внутри контейнера использует порт `80`, а пользователь открывает приложение через порт `8080`?** Что произойдёт, если не настроить публикацию порта?

4. **Какую роль выполняет Dockerfile при переносе приложения между компьютерами?** Какие проблемы он помогает решить и какие зависимости от внешней среды всё равно могут сохраниться?

5. **Представьте, что веб-приложение работает на вашем компьютере, но не запускается на другом Linux-сервере.** Как вы будете искать причину неисправности и какие преимущества Docker могут помочь избежать подобных ситуаций?
